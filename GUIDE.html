00

The month, as a loop

Kakeibo is not a spreadsheet with better manners. It is a four-beat cycle, and the app is built around that cycle rather than around transactions. Everything below follows it in order.

FIRST Plan Set income, fixed costs and a savings goal. What survives is the month’s spending money. DAILY Log Enter each spend by hand, into one of four buckets, with a note. ANYTIME Read Watch the pace, the weeks and the categories move against last month. LAST Close Answer the four questions, write the note, carry the plan forward.

Then it starts again — the reflection you write in step four is what changes the plan in step one.

01

Starting it up

Two processes in development: the API, and the interface that talks to it.

# terminal one — the API on port 2455
$ cd ~/Office/kaKeiBo/backend
$ source .venv/bin/activate
$ uvicorn app.main:app --reload --port 2455
# terminal two — the interface on port 8004
$ cd ~/Office/kaKeiBo/frontend
$ source ~/.nvm/nvm.sh && nvm use   # reads .nvmrc → Node 22
$ npm run dev

Open http://localhost:8004 in a browser.

Or as one process

Build the interface once and the API serves it too — a single port, no Node running:

$ cd ~/Office/kaKeiBo/frontend && npm run build
$ cd ../backend && uvicorn app.main:app --port 2455

Then open http://127.0.0.1:2455 in a browser — rebuild it whenever you change the interface.

02

Plan the month

Top of the right-hand column. This is the step that makes it kakeibo rather than expense tracking: savings come off the top, before you are allowed to spend anything.

The three figures, and what belongs in each
FieldWhat goes in
Income Everything arriving this month — salary, freelance, rent received, interest. Money you actually have, not money you expect.
Fixed costs Committed and unchanging: rent, EMIs, school fees, insurance, utilities, subscriptions. The test is whether spending less this month would change the figure. If it would, it is not fixed — it is a Need, and gets logged as an entry instead.
Savings goal What you are removing from circulation before the month starts. Set it first and treat it as already gone.

As you type, the card shows the spending money that survives: income − fixed costs − savings goal. That single figure is the budget for everything else, and it drives the daily allowance, the pace line and every verdict the app writes. Press Save plan.

Next month

A fresh month arrives blank and offers last month’s figures — “July 2026 was set up with ₹1,20,000 income…” with a Use those figures button. Nothing is copied without you asking; the button just saves the retyping.

03

Log as you go

The Ledger card, below the plan. Date, amount, bucket, note — then Add. The date is clamped to the month you are viewing, so to back-fill an older month, switch to it first with the arrows at the top.

The four buckets

Sort by why you bought it, not by what it was or where you bought it. The same cup of coffee is a Need on the way to work and a Want on a Sunday afternoon. That distinction is the entire method — get it wrong and the app has nothing useful to tell you.

Needs 必要 · HITSUYŌ

Groceries, transport, medicine, bills, anything you would have to buy again next month to keep going.

Would skipping this cause a real problem?

Wants 欲求 · YOKKYŪ

Eating out, clothes beyond replacement, treats, films, gadgets. Pleasant, optional, and the first place to trim.

Did I buy this because I wanted it, not because I needed it?

Culture 文化 · BUNKA

Books, courses, museums, music, temple visits. Self-enrichment gets its own bucket precisely so it is not quietly cut first.

Does this leave me with something I did not have before?

Unexpected 予期せぬ · YOKI SENU

Repairs, medical bills, gifts, fines. Things you could not have planned for this month.

Could I have seen this coming a month ago?

Write notes consistently

The note is not decoration — the leak finder groups entries by their exact wording. Log coffee every time and twelve of them add up into a finding. Log Coffee, cafe and chai for the same habit and they stay invisible. Pick a word per habit and reuse it.

Entries appear underneath, grouped by day with a running day total. Hover an entry for the delete button. There is no edit-in-place — delete and re-add is the fastest correction.

04

Read the screen

Everything is scoped to the month named at the top. Change it and every number and chart on the page re-reads. There is nothing to refresh.

Panel by panel, top to bottom
PanelWhat it tells you
Left to spend The one number the page leads with, and the daily rate that keeps it intact for the days remaining. Flips to Over budget by in red once the spending money is gone.
Budget meter Share of the budget used, with a vertical today marker at the share of the month elapsed. Fill left of the marker means you are ahead of an even pace; that is the fastest read on the page.
Tiles Spending money, spent so far, saved so far, projected month-end, and the daily allowance.
Where it went over Written verdicts on what is running hot — pace, projection, categories climbing against last month, wants and unexpected running above their thresholds.
Where you pulled back The same logic in the other direction. This is the panel worth reading at the end of the month.
Patterns and leaks Repeat spends, no-spend days, your priciest weekday, weekend-versus-weekday ratio, biggest single day and largest single spend.
Where the money went The four buckets with share, entry count, and movement against the same stretch of last month. Each keeps its own colour whatever the month looks like.
Day by day A column per day. The dashed line is the daily allowance. Hover or tab to any day for its category breakdown; Table shows every figure without hovering.
Running total against pace Cumulative spending versus an even pace, with the spending-money ceiling drawn across. Where the solid line crosses the dashed one is the day the month tipped.
Week by week Calendar weeks, Monday start, clipped to the month. Each week gets a pro-rated share of the budget marked on its bar, with the full numbers tabled below.
Day of the week Average spend per weekday across the month. This is where a standing habit shows itself.
Recent months Up to twelve months of totals with the budget line marked. Click any bar to jump to that month.
A fair comparison

While a month is still running, every “versus last month” figure compares the same stretch — day 1 to today against day 1 to the same date last month. A month in progress is never measured against a finished one. Once the month ends, the comparison becomes whole-month automatically.

05

Close the month

Bottom of the right column. Kakeibo closes on four questions, and the app answers the first three from your entries so you can spend your attention on the fourth.

Question 1
How much money do I have? Income less fixed costs, and what remained spendable after the savings goal.
Question 2
How much would I like to save? The goal, and whether it is still standing.
Question 3
How much am I actually spending? Entry count, daily average, and the largest bucket.
Question 4
How can I improve? The app nominates its most serious finding as a starting point — then you write the real answer in the box below it and press Save reflection.

The note is stored with the month and is still there whenever you navigate back. Write it in plain language, for yourself: what happened, what caused it, and the single thing to change. One specific change beats five resolutions.

06

What the app decides on its own

The written findings are not vague encouragement — each one has a rule behind it. Worth knowing, so you can tell a real signal from a threshold being grazed.

leak
The same note logged 3 or more times, averaging 2% or less of the month’s spending per occurrence. Small and frequent. A big repeat — the weekly grocery run — is listed as a recurring cost instead, with no alarm attached.
wants > 30%
Flagged. Wants are the first thing kakeibo trims, so a third of the month going there is worth a look.
wants ≤ 20%
Noted approvingly. A lean split by kakeibo’s reckoning.
unexpected > 15%
Flagged, with a nudge toward a separate buffer so surprises stop eating money meant for something else.
culture
Never scolded for rising, never congratulated for falling. It is the one bucket the method asks you to protect when you cut, so a drop is reported as something to notice rather than an achievement.
projection
Needs at least 3 days of the current month logged before it will guess at a month-end total.
no-spend days
Counted and reported once you reach 5 of them.
weekend ratio
Flagged when an average weekend day costs more than 1.3× an average weekday.

All of it lives in one file, backend/app/analytics.py — change a threshold there and the whole page follows; the interface only renders what that file decides.

07

Housekeeping

Your data

Everything lives in backend/kakeibo.db — to back it up, stop the server and copy that file — along with kakeibo.db-wal and kakeibo.db-shm if they are present. Copying it back is the whole restore procedure.

Changing currency or number format

Set these before starting the API. It currently runs as rupees with Indian lakh grouping.

$ export KAKEIBO_CURRENCY="$"
$ export KAKEIBO_LOCALE="en-US"

08

When something breaks

The three you are most likely to meet
What you seeWhat to do
“The ledger could not be opened” The API is not answering. Start it: uvicorn app.main:app --reload --port 2455, then press Try again.
“Oops, Node v16.20.2 detected” The terminal did not load nvm. Run source ~/.nvm/nvm.sh && nvm use in that tab, then npm run dev again.
Port 2455 already in use Pick another and tell both sides: start uvicorn with --port 8010, and run the interface with KAKEIBO_API=http://127.0.0.1:8010 npm run dev.

One last thing, and it is the point of the whole exercise: kakeibo was designed to be written by hand because the writing is what makes the spending conscious. Typing an entry is the modern equivalent — the pause is the feature. Log it at the moment it happens, not in a Sunday catch-up session, and the four questions will have something honest to work with.
